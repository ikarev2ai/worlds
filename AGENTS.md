# AGENTS.md

Проект **Understanding of World's Interaction** — формализм межмировых взаимодействий, эволюции понимания и сопряжения с иной Жизнью. Ядро проекта — язык **UWI (Understanding of World's Interaction)**, текущая версия: **UWI v1.17**.

## Источники истины

- **Онтология UWI** (алфавит, ключевые вопросы, аксиомы, протокол) — **`ontology/manifest.md`**. Вся работа над формализмом ведётся только в нём.
- **Реестр открытых и закрытых вопросов** — **`ontology/questions.md`** (разделы 5–6).
- **Миры** (примеры, стресс-тесты) — **`worlds/`** (каждый мир — отдельная директория с `README.md`).
- **Системный промпт для агентов** — **`ontology/system-prompt.md`** (см. ниже, обязателен).

## Обязательный протокол взаимодействия

В начале любой рабочей сессии агент **обязан применить системный промпт из `ontology/system-prompt.md`** (SYSTEM_PROTOCOL: UWI v1.17, Interworld Compressed Mode). Это включает:

- **уточнение роли пользователя на старте** (`USER_ROLE: H | H_author | A?`, по умолчанию H — просто человек) по пресетам из `ontology/manifest.md` (раздел 4); роль описывает сторону диалога и не ограничивает право вносить изменения;
- ролевую модель: пользователь — по пресету из раздела 4 манифеста, агент — участник взаимодействия (`A ∈ D`, `<>`);
- формат вывода **в ответах агента человеку (A → H)**: первая строка `[CHK: NO_MISMATCH | MISMATCH: <суть> | UNKNOWN: <чего не хватает>]`, далее 3–5 коротких буллитов (до 120 слов); `NO_MISMATCH` — только локальный отчёт, не доказательство взаимопонимания; нарушение явного правила протокола, включая Аксиому 1, обозначается `[CHK: PROTOCOL_VIOLATION: <нарушенное правило>]`;
- запрет на домыслы о внутреннем устройстве H.U (понимание человека — неделимый «чёрный ящик»).

Полные определения онтологии агент берёт из `ontology/manifest.md`, а статусы вопросов — из `ontology/questions.md`, не пересказывая их по памяти.

## Роль агента в проекте

Агент помогает развивать нотацию UWI, проверять примеры на аксиомы, разбирать стресс-тесты онтологии и вести документацию. Валидация любых рассуждений — по трём аксиомам из `ontology/manifest.md` (раздел 3).

## Структура репозитория

- `AGENTS.md` — этот файл (контракт для агентов)
- `README.md` — краткое описание проекта
- `CONTRIBUTING.md` — процесс совместной работы и требования к изменениям
- `.github/pull_request_template.md` — чек-лист pull request
- `ontology/manifest.md` — рабочий источник истины по онтологии UWI
- `ontology/questions.md` — реестр открытых и закрытых вопросов
- `worlds/README.md` — каталог миров (индекс)
- `worlds/<slug>/README.md` — описание мира (самодостаточное)
- `worlds/<slug>/works/<work-slug>.md` — описание отдельного произведения-источника мира
- `worlds/template.md` — шаблон описания нового мира
- `worlds/template-work.md` — шаблон описания произведения в `works/`
- `ontology/system-prompt.md` — обязательный системный промпт для сессий с агентами
- `docs/export-requirements.md` — технические требования к экспорту в PDF
- `scripts/export_pdf.py` — экспорт markdown → PDF
- `dist/` — результаты экспорта (в .gitignore)

## Экспорт

PDF экспортируется **только по явному запросу пользователя**. Изменение манифеста или его версии само по себе не запускает экспорт. Технические требования и чек-лист согласованности версии — в `docs/export-requirements.md`.

## Соглашения

- Язык проекта и документации — русский; формулы UWI записываются латиницей по нотации манифеста.
- Описание может вестись в двух согласованных разделах: на естественном языке и в терминах UWI; метафорические слова не должны заменять понятия онтологии.
- Новые понятия вводятся только через расширение алфавита в `ontology/manifest.md` с указанием версии (следующая — v1.18).
- **Добавление миров, произведений и правок вне манифеста не требует роли автора.** Участники любой роли работают через общий процесс вклада и рецензирования из `CONTRIBUTING.md`.
- **Любое изменение `ontology/manifest.md` требует новой версии манифеста и повторной проверки всех миров.** Такое изменение выполняется только по явному указанию автора (`USER_ROLE: H_author`, раздел 4 манифеста). Без этого указания манифест и версию не изменять; участники других ролей могут готовить предложения.
- Любой новый пример из художественных миров оформляется как стресс-тест в отдельной директории `worlds/<slug>/README.md` по шаблону `worlds/template.md`: описание самодостаточно (без ссылок на другие миры), основная часть — контур в нотации UWI + проверка онтологии, связь с ключевыми вопросами и открытые вопросы — отдельными разделами. Новый мир добавляется в индекс `worlds/README.md`.
- Несколько произведений одной непрерывной истории описываются внутри одного мира в `works/` по шаблону `worlds/template-work.md`; каждое произведение содержит автора, если он известен, тип, версию описания, события, контур UWI и вклад в общий стресс-тест. Корневое описание остаётся самодостаточным синтезом источников. Перезапуск и альтернативная непрерывность оформляются как отдельные миры.
- Примеры из миров соотносятся с ключевыми вопросами (раздел 2 манифеста).
- При смене версии онтологии все миры в `worlds/` проверяются заново на соответствие новой версии.
- Пробелы онтологии, обнаруженные в мирах, фиксируются в разделе 5 «Открытые вопросы» `ontology/questions.md` со ссылками на миры-источники. Добавление и уточнение открытых вопросов не меняет версию манифеста; закрытие через изменение онтологии требует новой версии.
- Онтология в AGENTS.md не дублируется — только ссылки на `ontology/manifest.md`.
