# Участие в проекте

Проект развивается совместно. Добавлять миры и произведения, исправлять документацию, предлагать и готовить изменения в онтологию может любой участник. Роль `H_author` для подготовки вклада не требуется.

Роли `H`, `H_author` и `A` описывают сторону диалога, а не уровень доступа к содержательной работе. Единственное ролевое ограничение: любое изменение манифеста требует новой версии и выполняется только по явному указанию автора (`H_author`).

## Основные правила

- Источник истины по онтологии — `ontology/manifest.md`; не дублируйте её определения в других документах.
- Открытые и закрытые вопросы ведутся отдельно в `ontology/questions.md`.
- Любое содержательное рассуждение проверяется по трём аксиомам из раздела 3 манифеста.
- Изменения оцениваются по содержанию и проходят общее рецензирование независимо от роли участника.
- Правки вне манифеста не требуют решения автора. Слияние выполняется по правилам доступа репозитория.
- Любое изменение манифеста сопровождается новой версией и повторной проверкой всех миров. Без явного указания автора на смену версии манифест не изменяется.
- Вклад, подготовленный AI-агентом, перед принятием проверяет человек. Агенты следуют `AGENTS.md` и `ontology/system-prompt.md`.

## Порядок работы

1. Прочитайте `ontology/manifest.md` и относящиеся к задаче документы.
2. Создайте отдельную ветку. Если у вас нет прав записи в репозиторий, используйте форк.
3. Ограничьте одно изменение одной понятной задачей: новый мир, уточнение онтологии, исправление документации.
4. Выполните проверки из раздела ниже.
5. Создайте pull request по шаблону: опишите мотив, суть изменения и его связь с аксиомами и вопросами онтологии.
6. Участвуйте в рецензировании: обсуждайте конкретные формулировки, контуры и следствия, а не личность участника.

## Добавление мира

1. Создайте `worlds/<slug>/README.md` по `worlds/template.md`. Используйте уникальный slug латиницей в нижнем регистре через дефис.
2. Сделайте описание самодостаточным: не полагайтесь на сравнения с другими мирами и не требуйте читать их.
3. Опишите события, контур UWI и проверку применимости онтологии. Связь с ключевыми вопросами и открытые вопросы укажите в отдельных разделах.
4. Для нескольких произведений одной непрерывной истории добавьте карточки в `works/` по `worlds/template-work.md`. Перезапуск и альтернативную непрерывность оформляйте как отдельные миры.
5. Добавьте мир в индекс `worlds/README.md` с текущей версией онтологии.
6. Новые пробелы онтологии зафиксируйте в разделе 5 `ontology/questions.md` со ссылкой на мир-источник. Добавление и уточнение открытых вопросов не меняет версию манифеста.

## Изменение онтологии

- Любое изменение `ontology/manifest.md` требует новой версии, явного указания `H_author` и повторной проверки всех миров. Исключений для небольших или редакторских правок нет.
- Участник без роли автора может подготовить предложение. До явного указания автора на смену версии манифест и его версию не изменяйте.
- После получения указания синхронизируйте `ontology/system-prompt.md`, `README.md`, `AGENTS.md`, шаблоны, индекс и описания миров.
- Проверьте каждую из трёх аксиом и укажите, какие миры подтверждают изменение или выявили его необходимость.
- Новые понятия вводите через алфавит манифеста. Не заменяйте понятия онтологии метафорами.
- Выполните проверки согласованности из `docs/export-requirements.md`, включая повторную проверку всех миров. PDF не экспортируйте без явного запроса пользователя.

## Документация и оформление

- Основной язык — русский; формулы UWI записываются латиницей по нотации манифеста.
- Сохраняйте существующую структуру файлов и шаблонов.
- Проверяйте относительные ссылки, пути, номера разделов и упоминания версии.
- Не включайте в изменение сгенерированные файлы из `dist/`.

## Проверка перед pull request

- [ ] Изменение согласуется с тремя аксиомами UWI.
- [ ] Новый мир оформлен по шаблону и добавлен в `worlds/README.md`.
- [ ] Новые открытые вопросы отражены в `ontology/questions.md` со ссылками на источники, без изменения версии манифеста.
- [ ] Связанные документы обновлены, старые формулировки не противоречат новым правилам.
- [ ] Любое изменение манифеста сопровождается новой версией, явным указанием автора и повторной проверкой всех миров.
- [ ] Команда `git diff --check` завершается без ошибок.
- [ ] В `git status --short` нет посторонних или сгенерированных файлов.
- [ ] PDF создан только при наличии явного запроса пользователя.

Если пункт не относится к изменению, отметьте это в описании pull request.

## Рецензирование

Рецензировать могут все участники. Проверяйте самодостаточность описания, корректность нотации, соблюдение аксиом и полноту связанных правок. Замечания должны быть конкретными и воспроизводимыми.

Для вклада вне манифеста одобрение автора не требуется. Любое изменение манифеста принимается только с новой версией по явному указанию автора и после повторной проверки всех миров.
